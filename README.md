# Наш Клининг — сайт и CRM

Одно приложение Node.js / Express для Render Web Service: адаптивный лендинг, прайсы, заявка на уборку, PostgreSQL, админ-панель, галерея «до/после», необязательные Telegram-уведомления.

## Файлы
- \`index.html\` — текущий дизайн, анимации, открытый каталог с ценами.
- \`server.js\` — API, проверка заявок, админ, изображения и PostgreSQL.
- \`data/defaultPrices.cjs\` — стартовый прайс со всех присланных скриншотов (включая диваны и кресла).
- \`admin.html\` — административная панель по адресу \`/admin\`.
- \`privacy.html\` — информация об обработке заявок.
- \`render.yaml\` — пример Render Blueprint.

## Запуск на компьютере
Требуется Node.js 20+ и PostgreSQL для хранения данных.

\`\`\`bash
npm install
# скопируйте .env.example в .env и настройте значения самостоятельно
# переменные из .env задайте в окружении; сервер НЕ загружает .env автоматически
npm start
\`\`\`

Без \`DATABASE_URL\` публичный сайт и прайсы работают, но сохранение заявок, админ-статистика и загрузка работ ответят ошибкой 503. Для реального использования база обязательна.

## Render Web Service (НЕ Docker)
1. В Render создайте **New → Web Service** и выберите GitHub \`krygantt-dot/nashclining-\`, ветку \`main\`.
2. Runtime/Language = **Node**, Root Directory пустой, Build Command = \`npm install --omit=dev\`, Start Command = \`npm start\`.
3. Выберите нужный инстанс, Auto Deploy = On Commit.
4. В Render создайте PostgreSQL (либо используйте надёжную совместимую базу с резервным копированием). Скопируйте **Internal Database URL** для услуг Render в одном регионе.
5. Добавьте Environment Variables на Web Service:
   - \`DATABASE_URL\` — **полный приватный** URL PostgreSQL (обязательно).
   - \`ADMIN_USERNAME\` — ваш логин (например \`admin\`).
   - \`ADMIN_PASSWORD\` — ваш случайный пароль **от 12 символов** (обязательно).
   - \`NODE_ENV=production\`.
   - \`TELEGRAM_BOT_TOKEN\` и \`TELEGRAM_CHAT_ID\` — необязательно, для уведомлений.
6. Deploy latest commit. Проверьте \`/health\`: поле \`db\` должно стать \`ready\`.
7. Откройте \`https://<название-сервиса>.onrender.com/admin\` и войдите.
8. Проверьте тестовую заявку и её появление в админке, затем удалите тестовую запись.

**Важно:** Не вставляйте пароль и DATABASE_URL в репозиторий, скриншоты, сообщения или клиентский HTML. Эти значения принадлежат только настройкам Render. Render Free Web Service может засыпать при отсутствии трафика. Бесплатная PostgreSQL (если доступна) может иметь ограничения, срок хранения и отсутствие бэкапов; для настоящих заявок используйте базу с долговременным хранением и резервным копированием. Свой домен и HTTPS подключаются в Render отдельно.

## API
- \`GET /health\` — статус.
- \`GET /api/prices\` — публичный прайс.
- \`GET /api/projects\` — опубликованные работы.
- \`POST /api/bookings\` — заявка: \`{name,phone,city,service,details,preferredDate,preferredTime}\`.
- \`POST /api/admin/login\` — вход администратора.
- \`POST /api/admin/logout\` — выход.
- \`GET /api/admin/me\` — проверка входа.
- \`GET /api/admin/stats\` — статистика.
- \`GET /api/admin/bookings\` — до 300 последних заявок.
- \`PATCH /api/admin/bookings/:id\` — обновление статуса.
- \`DELETE /api/admin/bookings/:id\` — удалить заявку.
- \`GET /api/admin/prices\`, \`PUT /api/admin/prices\` — изменение цен.
- \`POST /api/admin/projects\` — загрузка двух изображений (JPG/PNG/WebP, до 4 МБ каждое).
- \`DELETE /api/admin/projects/:id\` — удаление работы.

Начальное создание таблиц происходит при первом подключении к PostgreSQL. Фотографии хранятся **в самой базе**, чтобы переживать перезапуски и перевыпуски Render, а не на эфемерном диске.

## Безопасность и эксплуатация
Для небольшого бизнеса реализация служит стартовой версией: проверка входа, cookie HttpOnly, ограничение запросов, проверка типа загружаемого файла, параметризованные SQL-запросы и экранирование текста в HTML.

Перед обработкой настоящих данных проверьте юридическую информацию на \`/privacy\`, укажите реквизиты владельца бизнеса и оформите необходимые согласия. Настройте резервное копирование PostgreSQL, ограничение доступа администраторов и ротацию паролей. Сессии хранятся в памяти одного Node.js процесса и пропадают после рестарта/деплоя — это нормально для данного односерверного MVP. Для нескольких инстансов нужна общая session-store. Telegram отправляет персональные данные заявки в указанный чат: включайте уведомления лишь для уполномоченного администратора и после оценки требований защиты данных.

## Google Maps — пять отмеченных городов
В разделе «Где работаем» всегда видна схема с точками: Минск, Бобруйск, Солигорск, Жлобин, Рогачёв. При выборе города обновляется ссылка «Открыть в Google Картах» и город в заявке.

Чтобы заменить схему **полноценной интерактивной Google Maps с пятью настоящими маркерами**:
1. В Google Cloud Console создайте проект, включите **Maps JavaScript API** и биллинг. Официальная документация: https://developers.google.com/maps/documentation/javascript/get-api-key
2. Создайте **browser API key**, ограничьте его **HTTP referrers** `https://nashclining.onrender.com/*` и собственным доменом (если будет), а в **API restrictions** разрешите **только Maps JavaScript API**.
3. В Render Web Service → Environment добавьте `GOOGLE_MAPS_BROWSER_KEY` со значением ограниченного ключа и сохраните; Render развернёт новую версию автоматически.
4. Обновите страницу. При успешной загрузке появляется настоящая Google Maps со всеми пятью маркерами; при отсутствии ключа/ошибке загрузки остаётся схема (без пустых фрагментов карты).

**Важно:** браузерные ключи в принципе доступны посетителям сайта, поэтому ограничения домена, API и квот обязательны для защиты от чужого использования и неожиданных расходов. Не передавайте ключ в сообщения и не помещайте в GitHub. Карта обозначает города выезда, а не конкретные адреса и не время прибытия.

Исправлены визуальные эффекты: бегущая строка замедлена и зациклена без скачка, рекламные подписи на первом экране больше не прыгают.
