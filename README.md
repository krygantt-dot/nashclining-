# Наш Клининг — сайт и CRM

Одно приложение Node.js / Express для Render Web Service: адаптивный лендинг, прайсы, заявка на уборку, PostgreSQL, админ-панель, галерея «до/после», необязательные Telegram-уведомления.

## Файлы
- `index.html` — текущий дизайн, анимации, открытый каталог с ценами.
- `server.js` — API, проверка заявок, админ, изображения и PostgreSQL.
- `data/defaultPrices.cjs` — стартовый прайс со всех присланных скриншотов (включая диваны и кресла).
- `admin.html` — административная панель по адресу `/admin`.
- `privacy.html` — информация об обработке заявок.
- `render.yaml` — пример Render Blueprint.

## Запуск на компьютере
Требуется Node.js 20+ и PostgreSQL для хранения данных.

```bash
npm install
# в Render задайте DATABASE_URL, ADMIN_USERNAME и ADMIN_PASSWORD в Environment
# на локальном компьютере экспортируйте их в окружение (или запустите без базы)
npm test
npm start
```

Без `DATABASE_URL` публичный сайт и прайсы работают, но сохранение заявок, админ-статистика и загрузка работ ответят ошибкой 503. Для реального использования база обязательна.

## Render Web Service (НЕ Docker)
1. В Render создайте **New → Web Service** и выберите GitHub `krygantt-dot/nashclining-`, ветку `main`.
2. Runtime/Language = **Node**, Root Directory пустой, Build Command = `npm install --omit=dev`, Start Command = `npm start`.
3. Выберите нужный инстанс, Auto Deploy = On Commit.
4. В Render создайте PostgreSQL (либо используйте надёжную совместимую базу с резервным копированием). Скопируйте **Internal Database URL** для услуг Render в одном регионе.
5. Добавьте Environment Variables на Web Service:
   - `DATABASE_URL` — **полный приватный** URL PostgreSQL (обязательно).
   - `ADMIN_USERNAME` — ваш логин (например `admin`).
   - `ADMIN_PASSWORD` — ваш случайный пароль **от 12 символов** (обязательно).
   - `NODE_ENV=production`.
   - `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — необязательно, для уведомлений.
6. Deploy latest commit. Проверьте `/health`: поле `db` должно стать `ready`.
7. Откройте `https://<название-сервиса>.onrender.com/admin` и войдите.
8. Проверьте тестовую заявку и её появление в админке, затем удалите тестовую запись.

**Важно:** Не вставляйте пароль и DATABASE_URL в репозиторий, скриншоты, сообщения или клиентский HTML. Эти значения принадлежат только настройкам Render. Render Free Web Service может засыпать при отсутствии трафика. Бесплатная PostgreSQL (если доступна) может иметь ограничения, срок хранения и отсутствие бэкапов; для настоящих заявок используйте базу с долговременным хранением и резервным копированием. Свой домен и HTTPS подключаются в Render отдельно.

## API
- `GET /health` — статус.
- `GET /api/prices` — публичный прайс.
- `GET /api/projects` — опубликованные работы.
- `POST /api/bookings` — заявка: `{name,phone,city,service,details,preferredDate,preferredTime}`.
- `POST /api/admin/login` — вход администратора.
- `POST /api/admin/logout` — выход.
- `GET /api/admin/me` — проверка входа.
- `GET /api/admin/stats` — статистика.
- `GET /api/admin/bookings` — до 300 последних заявок.
- `PATCH /api/admin/bookings/:id` — обновление статуса.
- `DELETE /api/admin/bookings/:id` — удалить заявку.
- `GET /api/admin/prices`, `PUT /api/admin/prices` — изменение цен.
- `POST /api/admin/projects` — загрузка двух изображений (JPG/PNG/WebP, до 4 МБ каждое).
- `DELETE /api/admin/projects/:id` — удаление работы.

Начальное создание таблиц происходит при первом подключении к PostgreSQL. Фотографии хранятся **в самой базе**, чтобы переживать перезапуски и перевыпуски Render, а не на эфемерном диске.

## Безопасность и эксплуатация
Для небольшого бизнеса реализация служит стартовой версией: проверка входа, cookie HttpOnly, ограничение запросов, проверка типа загружаемого файла, параметризованные SQL-запросы и экранирование текста в HTML.

Перед обработкой настоящих данных проверьте юридическую информацию на `/privacy`, укажите реквизиты владельца бизнеса и оформите необходимые согласия. Настройте резервное копирование PostgreSQL, ограничение доступа администраторов и ротацию паролей. Административные сессии хранятся в PostgreSQL в виде хешей токенов с ограниченным сроком действия, поэтому переживают перезапуск Node.js. При компрометации учётных данных смените ADMIN_PASSWORD и завершите активные сессии в базе данных. Telegram отправляет персональные данные заявки в указанный чат: включайте уведомления лишь для уполномоченного администратора и после оценки требований защиты данных.

## Бесплатная карта городов
Карта на странице «Где работаем» встроена в HTML и CSS, показывает пять интерактивных меток: **Минск, Бобруйск, Солигорск, Жлобин, Рогачёв**. Никаких API-ключей, регистрации или платного Google Maps API не требуется. Клик по метке выбирает город для заявки и предоставляет бесплатную ссылку для открытия города на обычных Google Картах. Фон — наглядная схема, а не подробная дорожная карта.

Анимация нижней строки автоматическая и медленная (160–180 секунд на цикл), без полосы горизонтальной прокрутки. Две декоративные водяные капли плавно движутся вокруг главной фотографии, третья периодически исчезает и появляется. При системном предпочтении reduced motion анимации отключаются.

## Автоматическая проверка GitHub Actions

При каждом новом коммите в `main` GitHub Actions устанавливает Node.js, проверяет синтаксис (`npm run check`) и запускает интеграционные тесты (`npm test`). Результат смотрите на вкладке **Actions** репозитория. Проверки без PostgreSQL не заменяют ручную проверку записи заявок после подключения Render.

## Автоматические тесты

Команда `npm test` проверяет доступность главной страницы, прайса, страницы конфиденциальности, входа и закрытых API без настоящей базы данных. `npm run check` проверяет синтаксис серверного JavaScript. Тестовые учётные данные существуют только внутри тестового процесса и не используются на сайте.


### Кнопки под уведомлением

Под **новыми** заявками в Telegram-боте выводятся **две кнопки в одном ряду**:
- **✈️ Написать в Telegram** — ссылка на Telegram-чат по номеру телефона клиента с черновиком приветствия. Если клиент запретил поиск по номеру или у него нет Telegram, открыть переписку не получится.
- **💬 Написать в WhatsApp** — ссылка на WhatsApp по тому же номеру, тоже с готовым черновиком. Сообщение не отправляется автоматически.

Кнопки появляются при корректном формате номера в заявке (включая белорусские номера `+375`, `80...`, `0...`). Если номер нельзя распознать, сообщение всё равно содержит введённый телефон и заявку в админке. Старые уведомления бот автоматически не редактирует — чтобы проверить изменения, отправьте **новую** тестовую заявку.

## Telegram: уведомления о новых заявках

После подключения бота каждая новая заявка сначала **сохраняется в PostgreSQL**, а затем отправляется в Telegram сразу после записи. В сообщении: номер заказа, имя, телефон, услуга, город, дата, время, комментарий и ссылка на админку. Очередь \`telegram_notifications\` хранится в PostgreSQL: если Telegram временно недоступен, сервер повторит отправку. Во время простоя бесплатного Render фоновая обработка приостанавливается до пробуждения сервиса.

Чтобы подключить Telegram без публикации секретов:

1. В Telegram откройте официального **@BotFather**, отправьте \`/newbot\`, задайте название и имя бота, скопируйте токен в безопасное место.
2. Откройте чат с новым ботом и отправьте \`/start\`. Для групп добавьте бота в целевой чат и отправьте команду (боту может понадобиться право писать в группу).
3. Узнайте \`chat.id\` получателя через приватный вызов Telegram Bot API \`getUpdates\` вашего бота после \`/start\` (см. официальную документацию Telegram Bot API). Для групп идентификатор часто отрицательный.
4. Откройте **Render → nashclining → Environment** и добавьте \`TELEGRAM_BOT_TOKEN\` (секретный токен) и \`TELEGRAM_CHAT_ID\` (ID вашего личного чата или группы). Сохраните — Render перезапустит сервис.
5. Откройте \`https://nashclining.onrender.com/admin\` → **Telegram**. Убедитесь, что обе переменные отмечены как заданные, нажмите **«Отправить тестовое сообщение»**.
6. Создайте заявку со своим тестовым номером и проверьте, что она появилась в админке и сообщение пришло в Telegram. Затем удалите тестовую запись.

**Секретный токен нельзя публиковать ни в GitHub, ни в чате, ни на скриншотах.** Если токен раскрыт, перевыпустите его через @BotFather. Выбирайте только личный или закрытый рабочий чат, поскольку сообщения содержат персональные данные клиентов. Наличие переменных в Render не гарантирует доставку: проверяйте тестом и статусом очереди в админке.

**Ограничение гарантии:** при сбое сразу после получения Telegram сообщения, но до записи статуса в базу, возможна повторная доставка одного заказа. Проверяйте номер заявки в заголовке сообщения.



## AI-консультант сайта (OpenAI API)

Сайт использует **OpenAI Responses API**, модель по умолчанию \`gpt-4o-mini\`. Никакой ключ API не публикуется в JavaScript/HTML сайта. На сервере доступны \`GET /api/ai/status\` и \`POST /api/ai/chat\`. Чат появляется на сайте только после установки ключа OpenAI API.

### Включение

1. Откройте https://platform.openai.com/api-keys и создайте секретный ключ API в своём проекте. **API оплачивается отдельно от подписки ChatGPT**; установите ограничения расходов в настройках платформы.
2. На **Render → nashclining → Environment** добавьте \`OPENAI_API_KEY\` (только секретный ключ в поле Render). Не отправляйте его в Telegram, GitHub, формы, скриншоты или чат с ассистентом.
3. Необязательная переменная \`OPENAI_MODEL\` задаёт модель. Рекомендуется начать с \`gpt-4o-mini\`; Render Blueprint содержит значение по умолчанию.
4. Сохраните настройки Render и дождитесь статуса **Live**. Откройте https://nashclining.onrender.com/api/ai/status — при подключённом ключе будет \`"enabled":true\`.
5. Откройте https://nashclining.onrender.com — появится плавающая кнопка **AI-консультант**. Попросите назвать цены на уборку и химчистку, проверьте ответы, затем нажмите **«Оформить заявку»** и подтвердите тестовую заявку.
6. Проверьте заявку в админке и Telegram. AI не создаёт заявку сам: клиент заполняет обычную форму и подтверждает отправку.

### Поведение и безопасность

- Подтягивает **актуальный прайс из PostgreSQL**; без БД используется базовый встроенный прайс.
- Консультирует по Минску, Бобруйску, Солигорску, Жлобину и Рогачёву. Не утверждает, что мастер свободен на конкретную дату, не обещает фиксированную цену сверх прайса.
- Цель — помочь подобрать подходящую услугу и добровольно перейти к заполнению заявки, без давления на клиента.
- Переписка **не сохраняется в PostgreSQL**: браузер передаёт до 10 коротких предыдущих сообщений для контекста. В запросах к OpenAI установлено \`store:false\`. Не просите отправлять телефон или адрес в AI-чат — только в отдельную форму заявки.
- Ограничение запросов: 20 в час и 6 за 2 минуты на IP; короткие сообщения, лимит ответа \`max_output_tokens:400\`, ограничение времени ожидания.
- API-ключ хранится только на Render. При ошибках или отсутствии ключа чат недоступен, а обычная заявка и телефон работают как прежде.
- Внешний API может быть платным и может быть недоступен из-за лимитов или отсутствия средств на API-балансе. Проверяйте фактические цены и использование на https://platform.openai.com/usage.

Текущий AI-чат работает **на сайте**. Для переписки с клиентами внутри Telegram нужен отдельный клиентский диалог с ботом (клиент должен сам написать ему). Внутренний бот уведомлений менеджеров не отвечает людям сам по себе.


## AI в личных Telegram-чатах (Telegram Business)

**Отличие от кнопок Telegram/WhatsApp:** ссылки для ответа открывают личную переписку. Чтобы AI действительно видел сообщения клиента и отвечал **от имени вашего Telegram-аккаунта**, нужно подключить бота через **официальный Telegram Business**. Он работает только с чатами, которые вы разрешили в настройках Telegram, и только после одобрения подключения в админке. Телеграм-бот, который только отправляет менеджеру заявки, не умеет читать обычную личную переписку.

### Подключение без передачи пароля Telegram

1. Убедитесь, что **OPENAI_API_KEY**, **TELEGRAM_BOT_TOKEN** и **TELEGRAM_CHAT_ID** уже заданы на Render → Environment. Ключи и пароли никому не передавать.
2. У @BotFather включите **Business/Secretary Mode** существующего Telegram-бота, который отправляет уведомления о заявках.
3. Войдите в https://nashclining.onrender.com/admin → раздел **Telegram** → блок **AI в личных Telegram-чатах**.
4. Нажмите **«Настроить приём сообщений»**. Этот шаг регистрирует защищённый webhook по HTTPS с секретом, сохранённым только в PostgreSQL. Если у бота уже установлен webhook другого сервиса, панель вернёт ошибку, не перезаписывая его.
5. В приложении Telegram владельца откройте **Настройки → Telegram Business → Чат-боты** (название меню может зависеть от версии Telegram). Выберите созданного бота, разрешите ему читать и отвечать, укажите **только рабочие чаты**. Для ответа боту требуется разрешение \`can_reply\`.
6. Вернитесь в админку, нажмите **«Обновить подключения»**, выберите свой Telegram-аккаунт и нажмите **«Одобрить»**. Подключения не одобряются автоматически.
7. Нажмите **«Включить AI-ответы»**. Теперь, когда клиент напишет в разрешённый Business-чат, AI сможет отвечать от вашего имени.

**Важно:** настройка webhook и его регистрация не активируют AI сами по себе: требуется подключение Telegram Business, одобрение владельца в админке и отдельное включение автоматических ответов. Для проверки используйте отдельный тестовый рабочий чат, не личные переписки.

### Логика общения

- AI получает **только сообщения выбранных Telegram Business-чатов**, отвечает по актуальному прайсу PostgreSQL и уточняет услугу, объём, город и удобное время. Подтверждение заказа и финальную стоимость оформляет человек.
- AI обозначает себя как виртуальный помощник. Заказы сам не создаёт и не обещает конкретное время.
- При просьбе о менеджере, жалобе, нестандартном вопросе или проблеме OpenAI диалог ставится **на паузу**, а менеджер получает сообщение в свой чат уведомлений.
- Когда владелец Telegram сам отвечает в диалоге, в котором AI уже работал, автоответы ставятся на паузу. Перезапустить их можно в админке → Telegram → **«Возобновить AI»**. Если владелец первым написал клиенту, это само по себе не блокирует последующие AI-ответы.
- В админке можно в любой момент отключить AI глобально, поставить конкретного клиента на паузу или отозвать разрешение подключённого Telegram-аккаунта.
- Входящие Business-уведомления проверяются по секретному HTTP-заголовку Telegram, а дубли одного \`update_id\` не порождают повторные AI-ответы. Обработка продолжается после перезапуска Render благодаря очереди в PostgreSQL.
- Последние текстовые сообщения рабочего диалога хранятся в PostgreSQL до 30 дней и используются как контекст для OpenAI. **Не подключайте AI ко всем личным перепискам**: данные и сообщения разрешённых клиентов будут передаваться OpenAI для обработки.
- Введены технические лимиты на число ответов. На бесплатном Render доставка может задерживаться при холодном старте сервиса.

### Проверка

1. После активации попросите знакомого написать в **разрешённый Telegram Business-чат**: «Хочу химчистку дивана».
2. Ожидайте ответа AI через несколько секунд: вопросы об услуге, цене, городе или объёме работ; он не должен утверждать, что уже записал клиента.
3. Напишите «Хочу поговорить с менеджером» — AI передаст чат консультанту, поставит диалог на паузу и известит менеджера.
4. Проверьте список чатов в админке и нажмите **«Возобновить AI»** после завершения разговора.

Официальное описание: https://core.telegram.org/bots/api#businessconnection
